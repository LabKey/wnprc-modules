# Housing Transfer Form

This markdown describes how the housing transfer form works and behaves in detail.

## Field Inputs

### ID

This is the animals ID. This input field is not editable. Users can add new rows for animals by using the above
 selection or by selecting a destination room/cage for an animal. 

### In Date

This is the In Date for the animals new room/cage. This date will become the out date for 
the previous animals housing record.

### Out Date

This is the Out Date for the animals. This field is not normally shown to users completing the form
since they do not need an out date. It is only included when viewing past housing records in case select 
users (with correct permissions) need to make changes (correct errors) to the housing form.

### Room

This is the animals destination room. This is retrieved from the ehr_lookups.room table.
Selecting "No Change" in this input signifies that the animal is not changing rooms OR cages. If users
need to transfer an animal within the current room to a different cage in the current room they should still 
select the room in the dropdown instead of "No Change."

### Cage

This is a lookup that fetches the current cages within the selected room. As such you can assume that if a cage
is in this list then it is within the current room. If you select "No Change" for room then this input will be
autofilled to "No Change" as well, with the ability to clear the input disabled. This ensures that "No Change" signifies
that an animal is not changing rooms or cages and is remaining in place.

It was decided that even if an animal does not move rooms or cages they still need to appear in the form and have a transfer
record created because if it was paired with another animal, then the reason for move will need to be present for both animals.

If a room and cage are selected then the form will fetch any animals within that destination room/cage and add them to 
a grid under the selected room. If room/cage are changed or cleared, then it will remove those animals from the grids it
just added them to. This ensures that users do not need to clear animals if they change cages or rooms.

### Condition

This field is autofilled. Select users with certain permissions can change this field. However, this should rarely happen.
This field is generated by following the housing transfer flow chart below.

https://app.smartdraw.com/share.aspx/?pubDocShare=813067F26319A4E9C902D40BAF974D23A1E

### Reason For Move

This field is required. It is a multiple selection and certain reasons will create additional inputs or actions.

- Breeding (13)
  - If breeding (code 13) is selected then a project input field is added.
This field is required to determine which project is assigned to the breeding reason.
Additionally, if breeding is selected then it will create a breeding encounter when the form
is submitted.
- code 9 (behavior) or 26 (other)
  - If either of these codes are selected then remarks becomes required.

### Remarks

Any additional remarks needed to make note of for the housing transfer. 

### Performed By

Free text initials for the housing transfer. Includes everyone who helped with the transfer. 
We are not able to use signed in device ID for users since people share devices behind the barrier.

### Actions
Row level actions. Currently only delete row.
